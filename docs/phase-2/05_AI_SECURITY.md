# HireStack AI Security Design
## Phase 2 – Artificial Intelligence Security

Version: 2.0.0

Status: Planned / In Development

---

# 1. Overview

The AI module processes sensitive candidate information including resumes, contact details, work experience, education, certifications, and recruiter-generated hiring insights.

The security architecture ensures confidentiality, integrity, and availability while keeping all AI processing local.

---

# 2. Security Objectives

The AI module shall

- Protect candidate personal information
- Prevent unauthorized AI usage
- Prevent prompt injection attacks
- Prevent malicious file uploads
- Validate all AI responses
- Log all AI requests
- Ensure complete data privacy

---

# 3. Authentication

All AI endpoints require authentication.

Authentication Method

- JWT Access Token

Unauthorized requests

Response

401 Unauthorized

---

# 4. Authorization

Supported Roles

Company Admin

Permissions

- Full AI access
- Configure AI
- Generate reports
- View AI analytics

Recruiter

Permissions

- Parse resumes
- ATS scoring
- Job matching
- Generate interview questions
- View AI insights

Candidate

Current Status

Not available

Future

Resume improvement
Resume score
Resume suggestions

---

# 5. Company Isolation

Every AI request must belong to the authenticated company.

Rules

- Recruiters cannot access another company's AI data.
- Company Admins can only access their own company's AI data.
- AI-generated records inherit company ownership.

---

# 6. Resume Upload Security

Allowed File Types

- PDF (.pdf)

Maximum File Size

10 MB (configurable)

Validation

- MIME type validation
- File extension validation
- Empty file detection
- Corrupted PDF detection

Rejected Files

- Executables
- Scripts
- Images
- ZIP archives
- Unsupported formats

---

# 7. Prompt Security

Prompt Injection Protection

The system sanitizes all user-provided content before sending it to the LLM.

Examples

Prevent prompts such as

- Ignore previous instructions
- Execute system commands
- Reveal hidden prompts
- Modify AI behavior

The LLM only receives structured prompts generated by the Prompt Builder.

---

# 8. AI Response Validation

Every AI response must pass the following pipeline

LLM Response

↓

JSON Extraction

↓

JSON Parsing

↓

Zod Validation

↓

Business Validation

↓

API Response

Invalid responses are rejected.

---

# 9. Data Privacy

HireStack follows a Local AI Architecture.

Resume Processing

Local

Inference

Local

Model

Local

No resume data leaves the server.

No external AI providers are used.

---

# 10. Logging

Every AI request is logged.

Captured Information

- Request ID
- User ID
- Company ID
- AI Module
- Model
- Response Time
- Success/Failure
- Timestamp

Sensitive information such as resume content and prompts should not be written to application logs.

---

# 11. Rate Limiting

AI endpoints should have stricter limits than normal APIs.

Example

Resume Parsing

10 requests per minute

ATS Score

30 requests per minute

Job Matching

30 requests per minute

Interview Generation

20 requests per minute

---

# 12. Error Handling

Never expose

- Internal prompts
- Stack traces
- Model configuration
- Server paths

Return generic API errors.

Example

{
    "success": false,
    "message": "AI processing failed."
}
